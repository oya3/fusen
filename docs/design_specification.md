# 付箋アプリ（Fusen） 設計仕様書

> 本書は **現在の実装（`src/Fusen/`）の内容を記述したもの** です。実装を変更した際は本書も併せて更新してください。

## 1. 概要・コンセプト

本アプリケーションは、Windows 11のデスクトップ環境で動作する、**超軽量・シンプル・完全ポータブル**な付箋（Sticky Notes）アプリケーションです。

### コアコンセプト
1. **完全ポータブル（システム非侵食）**:
   - レジストリや `%APPDATA%` などのWindowsシステム領域を一切汚さず、アプリ直下の `data/` ディレクトリ内にすべてのデータ・画像を完結して保存。
   - フォルダごと移動（USBメモリや別ドライブ等）しても、そのまま以前の状態で動作可能。
2. **極めて軽量・シンプル**:
   - 余計な装飾や重厚なフレームワークを排し、瞬時の起動と最小限のメモリフットプリントを実現。
3. **スマートな省スペース表示（1行目タイトル折りたたみ）**:
   - 1行目のテキストのみを表示する「薄型スリムバー」にワンクリックで切り替え可能。
   - デスクトップの邪魔にならず、見たいときだけ即座に展開。
4. **画像貼り付けのネイティブ対応**:
   - スクリーンショットやクリップボード画像を `Ctrl + V` でそのまま付箋内にインライン貼り付け。
5. **メモ一覧管理画面（マネージャー）**:
   - 付箋が多くなった場合でも一覧画面から素早く検索・フォーカス・デスクトップから剥がす（削除・非表示）が可能。

### 2.1. キーボードショートカット

付箋アプリ自体が持つショートカットは以下の2つ。これに加えて、bash キーバインドモード（§2.2・既定で有効）のキー操作が本文編集で使える。

| キー | 機能 | 備考 |
| :--- | :--- | :--- |
| `Alt + N` | 新しい付箋を作成 | bash キーバインドモードの有無にかかわらず常に使える。`Alt + N` は readline 側で使用しないため衝突しない |
| `Ctrl + N` | 新しい付箋を作成 | **bash キーバインドモードが有効な間は無効**（「1行下へ移動」が優先される）。既定では有効なので、通常は `Alt + N` を使う |
| `Ctrl + L` | メモ一覧管理画面を開く | bash 側に対応する操作が無いため常に使える |

メモ一覧管理画面を開く経路は `Ctrl + L` とタスクトレイの右クリックメニューの2つ。付箋のヘッダーには一覧を開くボタンを置かない（各付箋に常時必要な操作ではなく、ヘッダーはタイトルの表示幅を優先する）。
`Ctrl + V`（貼り付け）は `RichTextBox` 標準の動作で、画像がクリップボードにある場合のみ独自処理へ差し替わる。
付箋の削除に割り当てられたショートカットは**設けない**（入力中の誤操作でデータを失うため）。

### 2.2. bash キーバインドモード（既定で有効）

本文編集に GNU Readline / Emacs スタイルのキーバインドを与える。**既定で有効**であり、
`fusen.ini` に `[Bash] Enabled = false` を明示した場合のみ無効になる（`[Bash]` セクションが無い場合も有効）。
無効時はハンドラ自体を生成せず、既定の編集操作に一切関与しない。

| キー | 機能 |
| :--- | :--- |
| `Ctrl + A` / `Ctrl + E` | 行頭 / 行末へ移動 |
| `Ctrl + F` / `Ctrl + B` | 1文字 進む / 戻る |
| `Alt + F` / `Alt + B` | 1単語 進む / 戻る |
| `Ctrl + P` / `Ctrl + N` | 1行 上 / 下へ移動 |
| `Ctrl + @` / `Ctrl + Space` | 範囲選択の開始（マークをセット） |
| `Ctrl + W` | 選択範囲をカット（非選択時は直前の1単語を削除） |
| `Alt + W` | 選択範囲をコピー（非選択時は何もしない） |
| `Ctrl + K` | カーソルから行末まで削除（行末では改行を削除して次行を連結） |
| `Ctrl + U` | カーソルから行頭まで削除 |
| `Alt + D` | 直後の1単語を削除 |
| `Ctrl + Y` | 直前にキルしたテキストを貼り付け（ヤンク） |
| `Ctrl + D` / `Ctrl + H` | 1文字削除（Delete / Backspace） |
| `Ctrl + T` | 前後の文字を入れ替え（行末では直前の2文字） |
| `Ctrl + _` / `Ctrl + /` / `Ctrl + Z` | アンドゥ |
| `Ctrl + S` / `Ctrl + R` | インクリメンタル検索（前方 / 後方）。§2.3 参照 |
| `Ctrl + G` / `ESC` | マーク・選択のキャンセル |

* **マークによる範囲選択**: WPF の選択はアンカー位置と移動位置で表される。マークをアンカー、
  内部で保持する移動位置を `_point` とし、カーソル移動のたびに選択し直す。
  キャレットは選択設定後に移動位置側へ来るとは限らないため、`_point` を正とする。
* **キルとクリップボード**: キル（`Ctrl+W` / `Ctrl+K` / `Ctrl+U` / `Alt+D`）とコピー（`Alt+W`）の内容は
  キルバッファに加えてシステムクリップボードへも反映する。`Ctrl+Y` はキルバッファを優先し、
  空の場合のみクリップボードのテキストを貼り付ける。連続キルの追記（readline の kill-append）は行わない。
* **既存の操作との衝突**: 有効時は bash 側のハンドラを先に通すため、次の操作が使えなくなる。既定で有効なので、これが通常の状態となる。
  * `Ctrl + N`（新規付箋作成）→ 「1行下へ移動」になる。新規作成は `Alt + N`、`＋` ボタン、トレイから。
  * `RichTextBox` 標準の `Ctrl + B`（太字）/ `Ctrl + E`（中央揃え）/ `Ctrl + U`（下線）。
  * `Ctrl + L`（メモ一覧）は readline 側に対応する操作を割り当てないため、そのまま残る。
* **キー配列**: `Ctrl + @` は JIS 配列の `@` 単独キー（`Key.Oem3`）と US 配列の `Shift + 2` の双方を受ける。
  `Ctrl + _` は `Key.OemMinus` と `Key.OemBackslash` の双方を受ける。
  `Ctrl + /`（`Key.OemQuestion`）も同じアンドゥに割り当てる。端末では `Ctrl + _` と同じ制御コードになるため、
  Emacs / readline でも両者は同じ操作として扱われる。
  `Ctrl + Space` は日本語IMEに横取りされる環境があるため、`Ctrl + @` を代替として用意している。

### 2.3. インクリメンタル検索（isearch）

bash キーバインドモードの一部。`Ctrl + S`（前方）/ `Ctrl + R`（後方）で検索モードに入る。
検索モードは入力を横取りする状態であり、通常のキーバインドより先に処理される。

| 検索中のキー | 機能 |
| :--- | :--- |
| 文字入力 | 検索文字列に追加し、その都度一致箇所を選択する |
| `Backspace` | 検索文字列を1文字削る。空になったら開始位置へ戻る |
| `Ctrl + S` / `Ctrl + R` | 次 / 前の候補へ進む |
| `Ctrl + W` | カーソル位置に続く1単語を検索文字列に取り込む（Emacs の `isearch-yank-word-or-char` 相当） |
| `Ctrl + Y` | 直前にキルしたテキストを検索文字列に取り込む |
| `Enter` | 確定。一致箇所の末尾にカーソルを置いて検索を終える |
| `Ctrl + G` / `ESC` | 中断。検索を始めた位置へカーソルを戻す |
| 矢印キー・その他の修飾キー操作 | 検索を確定してから、そのキー本来の処理を行う |

* **検索バー**: 付箋の下部に検索中のみ表示する。`I-search:`（後方時は `I-search(逆):`）と検索文字列、
  および「見つかりません」「折り返し」の状態を表示する。配色は付箋のテーマ色に追従する。
* **文字入力の受け口**: `PreviewTextInput` で受ける。`PreviewKeyDown` のキーコードからでは記号・かなを
  正しく取れず、IME で確定した文字も拾えないため。検索中はこのイベントを `Handled` にして、
  入力が本文へ入るのを止める。
* **大文字小文字**: Emacs と同じスマートケース。検索文字列が全て小文字なら区別せず、
  大文字を1つでも含めば区別する。
* **折り返し**: 末尾（先頭）まで到達したら自動的に反対の端から探し直し、検索バーに「折り返し」と表示する。
* **走査方式**: 本文を1本の文字列へ平坦化し、文字位置から `TextPointer` を引ける対応表を同時に作る。
  段落の終わりには改行を1文字挿入する。これが無いと前の行の末尾と次の行の先頭が地続きに見え、
  行をまたいだ誤一致や `Ctrl + W` での単語の取り込みすぎが起きる。
  一致範囲の終端は「次の文字の位置」ではなく「最後の文字の直後」を使う。
  次の文字は別の段落に属することがあり、その位置まで選ぶと改行が選択に含まれてしまうため。
* **検索の終了**: 本文からフォーカスが外れたとき、および付箋を折りたたんだときは確定して終了する。

### 3.1. データ・設定ファイルの探索規則

`data/` と `fusen.ini` は、配布時と開発時のどちらでも同じ場所を指すよう次の順で解決する。

* **`data/`**（`StorageService`）: 実行ファイル直下から4階層上の `data/` が存在すれば開発環境とみなしてそれを使用。無ければ実行ファイル直下の `data/` を使用。
* **`fusen.ini`**（`AppConfig`）: 実行ファイル直下に存在すればそれを使用。無ければ4階層上（リポジトリ直下）の `fusen.ini` を使用。どちらにも無ければ既定テンプレートで新規作成する。

## 4. UI / UX 仕様

### 4.1. 付箋ウィンドウ（NoteWindow）
* **スタイル**: 枠なし（`WindowStyle="None"`, `AllowsTransparency="True"`）、角丸（CornerRadius: 8px）、Windows 11調のドロップシャドウ（BlurRadius 12 / ShadowDepth 3 / Opacity 0.25）。ドロップシャドウ用に外周8pxのマージンを持つ。
* **サイズ制約**: 最小幅200px。展開時の最小高120px。既定サイズは `fusen.ini` の `[Note] Width / Height`（既定 280 × 300）。
* **ヘッダー部（ツールバー・高さ28px）**:
  * `＋` : 新しい付箋を追加（`Alt + N`）。現在の付箋の右下30pxの位置に作成。`Ctrl + N` でも同じ動作をするが、bash キーバインドモード（既定で有効）の間は使えない。
  * `📌` : 最前面固定（ピン留め）トグル。OFF時はアイコンを45%の不透明度で表示。
  * `🎨` : カラー＆不透明度・文字サイズポップアップを開く
  * `👁 / ✏` : Markdownプレビュー / 編集の切り替え（§4.5 参照）
  * `▲ / ▼` : 折りたたみ（スリムタイトルバー化）/ 展開切り替え
  * `✕` : 付箋削除（デスクトップから剥がす）。**確認ダイアログは表示せず即座に削除する。**
  * 左側にはタイトル（1行目テキスト）を表示。幅はヘッダーからツールボタン群を除いた残り全部を占め、収まらない場合のみ末尾を `…` で省略する（全文はツールチップで表示）。
  * タイトルの上下余白は明示指定せず、ヘッダー高と行ボックス高の差を `VerticalAlignment="Center"` が等分した結果とする。
    `FontSize="13"`・システム既定フォント（Yu Gothic UI）での行ボックスは 17.29px、上下の余白は各 5.35px。ツールボタン（24px）の上下は各 2px。
* **カラー＆不透明度・文字サイズポップアップ（`🎨`）**:
  * 登録済みテーマを丸ボタンで横並び表示（`[CustomTheme]` / `[Theme.<Name>]` で追加したテーマも含む）。
  * 不透明度スライダー（20〜100%）と現在値のパーセント表示。
  * プリセットボタン 4種: 100% / 85%（推奨） / 70% / 50%。
  * 変更はウィンドウ全体の `Opacity` に即時反映し、付箋ごとに保存される（下限0.1でクランプ）。
  * 文字サイズスライダー（9〜36、0.5刻み）と現在値の表示。**その付箋にのみ**適用され、付箋ごとに保存される。
    `fusen.ini` の `[Note] FontSize` は新規作成時の初期値という位置づけ。
  * 文字サイズの変更は本文全体（`TextRange.ApplyPropertyValue`）へ適用する。
    本文の XAML には `FontSize` が要素ごとに焼き込まれるため、コントロール側の指定だけでは既存のテキストに反映されないため。
  * フォントの種類（`FontFamily`）はポップアップからは変更できない。`fusen.ini` でのみ指定する。
* **折りたたみ表示（省スペースモード）**:
  * 折りたたみ時はウィンドウ高が **44px 固定**（ヘッダー28px + 上下の影マージン8px×2）に変形し、本文領域は `Collapsed` となる。
    この値は `NoteWindow.FoldedWindowHeight` に定数として持つ。ヘッダーの高さを変えたら合わせて更新すること。
  * 1行目のテキストのみがタイトルとして表示される。
  * ヘッダーのダブルクリックまたは `▲/▼` ボタンで折りたたみ直前の高さへ即座に復元。
  * 折りたたみ中のリサイズは左右のみ許可（高さは固定）。
* **リサイズ**: `WM_NCHITTEST` を独自処理し、外周8px + 判定幅8pxの領域を掴んでリサイズする。展開時は8方向、折りたたみ時は左右2方向。
* **本文領域**:
  * `RichTextBox` によるテキスト編集 & 画像インライン表示。文字サイズは付箋ごとの設定（未設定なら `fusen.ini` の `FontSize`）、フォントの種類は `fusen.ini` の `FontFamily` を適用。
  * `Ctrl + V` でクリップボードの画像を直接貼り付け。画像は付箋の幅に追従して表示される（下記）。
  * 貼り付けた画像の右クリックメニュー: 「📋 画像をコピー」「🗑️ 画像を削除」。
* **画像の表示サイズ（レスポンシブ）**:
  * 本文中の画像は付箋の幅に収まるよう `MaxWidth` を都度設定する。固定の上限を持たせると、
    付箋を広げても小さいままになり、狭めると本文からはみ出すため。
  * **元のサイズより大きくは引き伸ばさない**（拡大するとぼやけるため）。実際の上限は
    「画像の原寸」と「表示可能な幅」の小さい方。高さの上限は設けず、縦横比は幅に従う。
  * 適用のタイミングは、本文の復元後（レイアウト確定後）、画像の貼り付け直後、
    およびウィンドウの幅が変わったとき。折りたたみ中は本文が隠れているため行わない。
  * 表示可能な幅は `RichTextBox.ViewportWidth`（取得できない場合は `ActualWidth` から
    パディングと枠線を引いた値）から、丸め誤差で横スクロールバーが出ないよう 4px 引いた値。
  * バインディングは使わない。本文は XAML として保存・復元されるため、バインディング式は
    保存時に失われ、復元後は追従しなくなる。リサイズのたびに再設定する方式を採る。
  * 段落の既定マージンは読み込み時・編集時に常時0へ正規化し、改行ごとの余分な行間を排除する。
* **インクリメンタル検索バー**: 本文の下に配置し、検索中（§2.3）のみ表示する。折りたたみ時は検索を終了して隠す。
* **タイトルの決定規則**: 本文の空行を除いた最初の行をそのまま使う（前後の空白のみ除去）。本文が空の場合は `新規メモ`。
  文字数による打ち切りは行わない。表示上の省略は各画面の `TextTrimming` に委ね、付箋を広げれば続きが見えるようにする。

### 4.2. メモ一覧管理画面（NoteListWindow）
* **検索バー**: 上部の検索窓に文字を入力すると、タイトルおよび本文からリアルタイムに絞り込み（大文字小文字を区別しない）。`✕` ボタンで検索条件をクリア。
* **並び順・件数**: 更新日時の降順で固定表示。ヘッダーに「全 N 件のメモ」を表示する。
* **メモ一覧カード**:
  * 各付箋のテーマカラー（ヘッダー色）、タイトル（1行目）、本文プレビュー、更新日時を表示。ピン留め中は `📌`、折りたたみ中は `🔽折りたたみ中` を併記。
  * **「🎯 開く」ボタン / ダブルクリック**: デスクトップ上のその付箋を表示・展開・最前面化する。
  * **「表示 / 非表示」切り替え**: デスクトップから一時的に剥がして保管、または再表示。
  * **「🗑️ 削除」ボタン**: 確認ダイアログ（はい/いいえ）を経て該当の付箋を削除する。
* **一括アクション**:
  * 「＋ 新規付箋」
  * 「▲ すべて折りたたむ」/「▼ すべて展開」（デスクトップに表示中の付箋が対象）
  * 「📂 データフォルダ」/「⚙️ 設定 (INI)」

### 4.3. タスクトレイ（NotifyIcon）常駐
* 時計の横（タスクトレイ）にアイコンを常駐。アイコンは起動時に描画生成する（外部ファイル不要）。
* **左クリック**: 新しい付箋を作成（位置は既定規則に従う。§4.4 参照）。
* **右クリックメニュー**:
  * 📝 新しい付箋を作成
  * 📋 メモ一覧マネージャー
  * 📂 データフォルダを開く
  * ⚙️ 設定 (fusen.ini) を開く
  * ─────
  * ▲ すべて展開 / ▼ すべて折りたたむ
  * ─────
  * 🚪 終了

### 4.4. 付箋の新規作成位置
* **ヘッダーの `＋` / `Ctrl + N`**: 元の付箋の右下30px。
* **トレイ・一覧画面から**: `100 + (現在の付箋数 % 8) × 30` を X/Y 座標とする階段状の配置。画面外にはみ出す場合は 100 に戻す。
* **初回起動時（`notes.json` が無い場合）**: 座標 (150, 150)、高さは既定値と320pxの大きい方で、操作方法を記したウェルカム付箋を1枚作成する。

### 4.5. Markdown プレビュー

本文を Markdown として描画した読み取り専用表示に切り替える。ヘッダーの `👁`（プレビュー中は `✏`）で切り替える。

* **Markdown かどうかは判定しない**。書いた本人が知っているため、ボタンによる明示的な切り替えのみとする。
  自動判定はパス中の `*` やコンソール出力の `#` を装飾と誤認するため採用しない。
* **編集用の文書には触れない**。プレビューは `Note.PlainText` から**別の** `FlowDocument` を生成し、
  `FlowDocumentScrollViewer` に表示する。編集用 `RichTextBox` の文書を書き換えると `TextChanged` が走り、
  整形結果で `contentXaml` が上書きされて元の Markdown ソースが失われるため。
* **状態の保存**: `notes.json` の `isPreview` に保存し、起動時に復元する。本文の復元後に適用する。
* **画像は表示しない**。貼り付け画像は `FlowDocument` 側に保持され `plainText` に含まれないため、
  プレビューには出ない。Markdown の画像記法 `![alt](url)` は `[画像: alt]` という文字として描画する。
* **リンク**: クリックで既定のブラウザを開く。不正な URI はリンクにせず文字として表示する。
* **配色・文字サイズ**: 付箋のテーマ色と文字サイズに追従する。テーマや文字サイズを変更すると描画し直す。
* **検索との関係**: プレビューに入るとインクリメンタル検索は終了する（本文が編集用ビューから隠れるため）。

#### 対応する記法（Markdig 1.3.2 + PipeTables + AutoLinks）

見出し（h1〜h6、h1/h2 は下線付き）、段落、強調（太字・斜体・打ち消し）、インラインコード、
コードブロック（フェンス・インデント）、箇条書き・番号付きリスト（開始番号を保持）、引用、水平線、
リンク・自動リンク、表（ヘッダ行は太字・背景付き）。

未対応のブロック・インラインに遭遇した場合は、**元のテキストをそのまま出力する**フォールバックを設けており、
内容が黙って消えることはない。

## 5. データ構造 & ストレージ設計

### 5.1. `notes.json` のスキーマ

キーは camelCase、インデント付きで出力する。

```json
{
  "version": 1,
  "notes": [
    {
      "id": "c3b9e4a1-7d2f-48e2-9d33-918274aef001",
      "x": 100.0,
      "y": 150.0,
      "width": 280.0,
      "height": 320.0,
      "isFolded": false,
      "foldedHeight": 42.0,
      "isPinned": true,
      "isVisible": true,
      "isPreview": false,
      "opacity": 0.85,
      "fontSize": 13.5,
      "colorTheme": "Yellow",
      "contentXaml": "<FlowDocument ...>...</FlowDocument>",
      "plainText": "買い物リスト\n- 牛乳\n- パン",
      "title": "買い物リスト",
      "createdAt": "2026-08-29T13:20:00Z",
      "updatedAt": "2026-08-29T13:25:00Z"
    }
  ]
}
```

* `height` は**展開時の高さ**を保持する。折りたたみ中に保存された場合も、折りたたむ直前の高さを書き出す。
* `opacity` は付箋ごとのウィンドウ不透明度（0.1〜1.0）。0以下の場合は `fusen.ini` の既定値を使用する。
* `isPreview` は Markdown プレビュー表示中かどうか。項目が無い旧形式では `false` として扱う。
* `fontSize` は付箋ごとの本文の文字サイズ（9〜36）。0以下または項目が無い場合は `fusen.ini` の `[Note] FontSize` を使用する。
  この項目を持たない旧形式の `notes.json` もそのまま読み込める。
* `foldedHeight` は `NoteItem` のプロパティとして出力されるが、**現在の実装では読み書きされていない**（折りたたみ時の高さは44px固定）。

### 5.2. カラーパレット定義

各テーマは7つのブラシを持つ。`Background` / `Header` / `Border` / `Foreground` / `HeaderForeground` は `fusen.ini` から上書き可能（`#RRGGBB` または `#AARRGGBB`）。`ButtonHover` / `IconColor` は内部で生成されるが、**現在の実装では描画に使用していない**（ヘッダーボタンのホバーは固定色 `#22000000`）。

| テーマ | Background | Header | Border | Foreground | HeaderForeground |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Yellow**（イエロー） | `#FFFDE7` | `#FFF59D` | `#FFF176` | `#212121` | `#3E2723` |
| **Green**（グリーン） | `#E8F5E9` | `#C8E6C9` | `#A5D6A7` | `#212121` | `#1B5E20` |
| **Blue**（ブルー） | `#E1F5FE` | `#B3E5FC` | `#81D4FA` | `#212121` | `#01579B` |
| **Pink**（ピンク） | `#FCE4EC` | `#F8BBD0` | `#F48FB1` | `#212121` | `#880E4F` |
| **Purple**（パープル） | `#F3E5F5` | `#E1BEE7` | `#CE93D8` | `#212121` | `#4A148C` |
| **Dark**（ダーク） | `#2B2D30` | `#1E1F22` | `#3C3F41` | `#E0E0E0` | `#FFFFFF` |

* **`[CustomTheme]`**: `Custom` という名前のテーマを追加登録する。`fusen.ini` の `[Note] ColorTheme = Custom` で既定テーマにもできる。
* **`[Theme.<Name>]`**: 既存テーマ（例 `[Theme.Yellow]`）の色を部分的に上書きする。存在しない名前を書けば新規テーマとしてパレットに追加される。指定しなかったキーは元のテーマ値、または Yellow の値を引き継ぐ。
* 未知のテーマ名が `notes.json` に入っていた場合は Yellow へフォールバックする。

### 5.3. `fusen.ini` の設定項目

| セクション | キー | 既定値 | 範囲・備考 |
| :--- | :--- | :--- | :--- |
| `[Note]` | `Width` | 280 | 200〜2000 |
| | `Height` | 300 | 120〜2000 |
| | `ColorTheme` | Yellow | 登録済みテーマ名。旧キー `Color` も読み取る |
| | `Opacity` | 1.0 | 0.10〜1.00、または 10〜100（%表記） |
| | `Pinned` | false | 新規作成時に最前面固定するか |
| | `FontSize` | 13.5 | 9.0〜36.0。新規作成時の初期値。以後は付箋ごとに `🎨` から変更する |
| | `FontFamily` | Segoe UI, Yu Gothic UI, Meiryo | 全付箋共通。付箋ごとの変更手段は設けない |
| `[Backup]` | `Enabled` | true | |
| | `Generations` | 5 | 1〜100 |
| | `IntervalMinutes` | 10 | 1〜1440 |
| `[Bash]` | `Enabled` | true | bash キーバインドの有効化。§2.2 参照 |
| `[CustomTheme]` | `DisplayName`, `Background`, `Header`, `Border`, `Foreground`, `HeaderForeground` | §5.2 参照 | |
| `[Theme.<Name>]` | 同上 | 元テーマの値 | §5.2 参照 |

* `[Note]` は旧セクション名 `[General]` でも読み取る。
* リポジトリ直下の `fusen.ini` を唯一の正とし、`Fusen.csproj` からリンク参照でビルド出力へコピーする（プロジェクト内に複製を置かない）。

## 6. 非機能要件・ポータブル方針

1. **ゼロ・システム侵食**:
   - レジストリ、`%APPDATA%` は一切不使用。
   - 実行ファイル（またはスクリプト）と同じディレクトリの `data/` 配下ですべて完結。
2. **Crash-safe な自動保存**:
   - `notes.json` 更新時は一時ファイル（`notes.json.tmp`）へ書き込んだ後にアトミックリネームを行い、破損を防ぐ。
   - デバウンス（400ms）による快適な入力レスポンス。テキスト入力・移動・リサイズ・折りたたみ・色/不透明度/文字サイズ変更がすべて同じデバウンスを共有する。
3. **世代バックアップと自動復旧**:
   - 付箋データは単一の `notes.json` に保持する。実測では 1000 枚でも保存 10ms 未満・起動 20ms 程度であり、
     枚数増加による性能劣化は問題にならない。一方、1ファイルであるため破損時の被害が全付箋に及ぶ点が唯一の弱点となる。
     これを補うために世代バックアップを設ける（ファイル分割方式は起動時の I/O が桁違いに増え、
     「瞬時の起動」というコンセプトに反するため採用しない）。
   - 作成タイミング:
     - **起動時**: `notes.json` の読み込みに成功した直後に、間隔を無視して1世代。
     - **終了時**: 最終保存の後に、間隔を無視して1世代。
     - **稼働中**: 自動保存が成功したタイミングで、前回作成から `IntervalMinutes`（既定10分）以上経過していれば1世代。
       定期タイマーによる作成ではないため、操作が一切なければ稼働中の世代は増えない。
   - `notes.json` の最終更新日時が前回のバックアップ時から変化していない場合、および内容が空の場合は世代を消費しない。
   - `Generations`（既定5）を超えた古い世代は自動削除。ファイル名はミリ秒まで含む固定長とし、
     名前の昇順が作成順と一致することを保証する。
   - 復旧: 起動時に `notes.json` が破損・空だった場合、新しい世代から順に読み込みを試し、
     最初に成功したものを `notes.json` として復元する。読み込めなかった原本は削除せず
     `notes_corrupt_*.json` として `data/backups/` に保管し、結果は付箋表示後にダイアログで通知する。
4. **完全なポータビリティ**:
   - フォルダを丸ごと別のPCやUSBメモリにコピーしても、設定やデータがそのまま移行可能。
